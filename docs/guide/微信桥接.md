# 微信桥接部署

这是单一绑定用户的个人桥接；不需要开放公网端口。以下模板使用 ubuntu 用户与 /home/ubuntu/douyin-spark-flow 源码目录；不同安装路径必须修改服务模板。生产服务上线前先备份代码、配置、SQLite 一致性快照和服务定义，不要将备份上传 GitHub。

## 1. 共享私有运行目录

```sh
install -d -m 700 /home/ubuntu/douyin-weixin-validation
cp deploy/weixin-bridge.env.example /home/ubuntu/douyin-weixin-validation/bridge.env
chmod 600 /home/ubuntu/douyin-weixin-validation/bridge.env
set -a
. /home/ubuntu/douyin-weixin-validation/bridge.env
set +a
```

这些变量需同时传给 `python main.py chat` 和桥接 worker。默认路径兼容既有服务器；自定义部署须设置全部三个变量，使数据库和模式文件一致。chat 服务的 [Service] 可增加 `EnvironmentFile=/home/ubuntu/douyin-weixin-validation/bridge.env`。原抖音账户与模型配置仍在原应用中设置，不要复制公开。

## 2. 扫码绑定

手机先启用微信 ClawBot 插件，然后从仓库根目录运行：

```sh
.venv/bin/python -m core.ai.weixin_bind
```

程序打印 QR_READY，并在私有目录生成 qr.json；其中 qrcode_img_content 是扫码入口，可用可信的本地二维码工具显示，也可以在微信中打开该入口。不把入口贴到公共网站或 GitHub。二维码有效期取决于微信接口，过期重新运行；脚本不是图形界面。confirmed 后 binding.json 私有保存，回到 ClawBot 发一句话，为后续发送提供 context_token。不要手工在聊天或 README 填真实 token。已有绑定无需再次扫码。

## 3. 启动

前台调试（另一个终端运行已配置的 chat）：

```sh
.venv/bin/python -m core.ai.weixin_worker
```

systemd 服务模板：

```sh
sudo install -m 644 deploy/douyin-weixin-forward.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now douyin-weixin-forward.service
sudo systemctl status douyin-weixin-forward.service
```

worker 通过 getupdates 长轮询接收绑定用户指令，通过 sendmessage 返回纯文本；chat 浏览器线程负责抖音发送。不要同时运行多个 worker，也不要启动第二套浏览器抢同一个账号。状态 active 不代表消息送达：验证一次微信指令、一次抖音转发和明确目标发送，再核对手机实际结果。

## 4. 隔离测试

快捷回复检查使用临时 SQLite、模式文件和假浏览器，不向真实好友发送：

```sh
.venv/bin/python tests/check_weixin_bridge.py
```

AI／会话测试也必须隔离状态，否则默认人工模式会改变旧 AI 测试的前提：

```sh
T=$(mktemp -d)
export DOUYIN_WEIXIN_DB="$T/queue.sqlite3"
export DOUYIN_REPLY_MODE_FILE="$T/mode.json"
export DOUYIN_SESSION_DIR="$T/sessions"
.venv/bin/python -c "from core.ai.reply_mode import set_mode; set_mode('ai')"
.venv/bin/python -m unittest tests.test_session_store tests.test_ai_chat
rm -rf "$T"
```

## 故障与恢复

上下文失效时先在微信发送一句话；blocked_context 仅在新上下文到来后重试。uncertain 表示结果未知，不自动重发；人工核对抖音或微信实际会话后再决定。重启时 sending 会转 uncertain。不要以旧队列覆盖新数据库，否则可能丢消息或重复发送；代码回滚应停止相关服务、恢复匹配代码和配置，数据库恢复需单独评估。

会话状态模块只保存已有认证状态，不延长登录有效期；失效仍需正常刷新登录。视频／图片消息只转文字标签或分享摘要，不表示已经观看或识别媒体内容。


## Docker 服务器常驻部署

新增 `docker-compose.chat.yml` 专用于常驻陪聊／桥接。原 `docker-compose.yml` 为定时续火花，且包含另一个 gost 服务及其端口，**不是**这套无公网端口桥接的启动文件。不要同时启动源码 chat 与容器 chat 管理同一账号。

要求 Linux amd64、Docker Engine 和 Compose v2；当前 Dockerfile 下载 x64 Chromium，不宣称支持 ARM64。先在可信电脑完成抖音登录与 AI 设置，将私有 `.env` 安全迁移至服务器 `config/.env`，不要在 GitHub 中填写 Cookie 或 API Key。已有绑定可安全迁移私有 binding.json，不必重新授权。

```sh
# 在仓库根目录运行；config/.env 必须是已有的真实配置文件
install -d -m 700 config config/sessions .weixin-bridge
test -f config/.env
chmod 600 config/.env
# 本地构建避免依赖账号的 GitHub Actions 可用性
docker compose -f docker-compose.chat.yml build chat
# 第一次绑定：手机先启用插件；该进程生成私有 qr.json 并等待扫码
docker compose -f docker-compose.chat.yml run --rm --no-deps   --entrypoint python weixin -m core.ai.weixin_bind
# 成功绑定后启动两个常驻容器
docker compose -f docker-compose.chat.yml up -d chat weixin
docker compose -f docker-compose.chat.yml logs --tail=100 -f
```

qr.json 在宿主机 `.weixin-bridge/`，其中 qrcode_img_content 是扫码入口；只用可信本地工具显示二维码或在微信打开链接。扫码后在 ClawBot 发一句话。容器共享 `/state`，保存队列、绑定、上下文和模式，chat 的浏览器会话另挂载持久化；无 `ports`，所有连接都是出站。镜像默认 root 运行，本模板的私有文件可能归 root 所有，非 root 运维需自行匹配 UID／目录权限，不能通过开放目录权限解决。

启动后先发“查看模式”“获取聊天列表”，再让已配置监听目标发送一条新消息，核对手机转发和明确编号的发送结果。AI 模式需要有效 AI 配置；不启用 AI 时仍需满足现有 chat 的账户／提供商配置校验。`restart: unless-stopped` 和服务 active 不是收发正常的证明。

如需已发布镜像，先确认 Actions 成功且 GHCR tag 存在，再设置 `DOUYIN_IMAGE=ghcr.io/aqiux17/douyinsparkflow:sha-COMMIT`（使用实际 tag），执行 `docker compose -f docker-compose.chat.yml pull` 和 `up -d`。私有镜像需先登录 GHCR；没有公开镜像时使用本地 build。
